# Contributing

## Building and testing

```console
$ swift build -c release        # produces .build/release/am
$ swift test
```

Needs Xcode 16 or later (`Package.swift` is swift-tools-version 6.0).

The interactive paths — the menus, the masked key prompt, the signal handling —
are covered by driving the real binary through a pseudo-terminal
(`Tests/amTests/TerminalSession.swift`). Those suites are `.serialized`: a pty
is a limited resource, and enough of them opening at once gets `ENXIO` from
`openpty`, which reads as a failure but is only contention.

The `Tests` workflow runs on every push, so a break shows up long before a
release.

To try your build without disturbing an installed copy:

```console
$ export PATH="$PWD/.build/release:$PATH"
$ am --version      # dev
```

## Releasing

Push a tag starting with `v`; the rest happens on its own:

```console
$ git tag v0.1.4
$ git push origin v0.1.4
```

GitHub Actions takes it from there:

1. Writes the tag's version into `Sources/am/Version.swift`
2. Runs the tests
3. Builds the universal binary (arm64 + x86_64)
4. Creates the GitHub Release with `am-<version>-macos-universal.tar.gz`
5. Computes the sha256, regenerates `Formula/am.rb` in
   [tom19830924/homebrew-tap](https://github.com/tom19830924/homebrew-tap), and
   pushes it

Users get it with `brew update && brew upgrade am`.

### One place decides the version

`Version.swift` holds the placeholder `dev`. The real version exists only as a
git tag and is written in just before the build, so a published binary cannot
disagree with the tag it was published under — not because something checks,
but because only one number is ever in play. A local build reports `dev`, which
is true: it is not a release.

If the write matches nothing, or the built binary reports a version other than
the tag, the workflow stops and nothing is published.

### Rehearse without publishing

The **Release** workflow has a Run workflow button. Give it a version, leave
"Build and package only" ticked, and it runs the tests and the build without
touching the Release or the tap, leaving the result downloadable as an
artifact.

Use a tag for a real release, so the version stays tied to a commit.

### Notes for whoever maintains this

- `Formula/am.rb` is generated by CI; don't hand-edit the tap
- CI pushes the formula with the `TAP_WRITER` repo secret: a fine-grained token
  scoped to `homebrew-tap` alone, with write access to contents and nothing
  else. When it expires, a release stops at "Check out the tap" — the Release
  still appears, but the formula quietly stays on the old version
